# Existing four DLCs — six-standard-storefront implementation readiness (v1.25.3)

Status: **CORE_SIX_STORE_STATIC_TESTED / FOUR_ADDITIONAL_PACKNAMES_INFERRED / WRITER_NOT_ACTIVATED**.

This research is deliberately separate from the November 18 new-expansion identification. No claim of Epic, Microsoft, Sony or Mac App Store compatibility is made merely because a synthetic six-store test passed.

## Source verification

The original private static research archive `DDV_DLC_PATCHER_MULTIPLATFORM_STATIC_RESEARCH_REV2_20261118.zip` was opened and its three actual members were inspected:

- `DDV_DLC_PATCHER_MULTIPLATFORM_FEASIBILITY_20261118.md`
- `DDV_v1253_MULTIPLATFORM_EVIDENCE_20261118.json`
- `ddv_multiplatform_evidence_20261118.py`

Original Steam v1.25.3 `protoDb.bin` provenance recorded in the archive: 1,164,172 bytes, SHA-256 `1912bb552abddac8b112fa5a781a0401672add38a62276d6c9174db39b899ae1`. It reports 49 IAP definitions and 7 StoreFrontGroups, one of which is `AppleArcade` and must not be patched. The other six group names are `Nintendo`, `Steam`, `Epic`, `Microsoft`, `Sony`, `Apple`. Every one of the four original expansion-pass IAP UniqueNames has marketplace product records for the six ordinary groups.

The four IAP UniqueNames recorded in original `protoDb.bin` evidence are:

| DLC | `LastKnownBoughtExpansionsAnyPlatform` | IAP `UniqueName` |
|---|---|---|
| A Rift in Time | `Expansion01` | `Expansion1PackExpansionPass` |
| The Storybook Vale | `Expansion02` | `Expansion2PackExpansionPass` |
| Wishblossom Ranch | `Expansion03` | `Expansion3PackExpansionPass` |
| Honeyglow Woods | `WinnieDLC` | `MiniExpansion1PackExpansionPass` |

A genuine v1.25.3 Steam encrypted profile separately establishes saved `Nintendo` and `Steam` map keys and their eight original pass entries. Nintendo/Steam `PackName` matches `UniqueName + "_" + StoreFrontGroup.UniqueName + "_OnlineKey"`. The v1.25.3 Switch native method `IAPData.get_KeyFriendlyId` constructs a four-part concatenation using IAP UniqueName and the current StoreFrontGroup UniqueName, then supplies the key to `Profile.ApplyExpansionsOwnershipStatus`. The literal separator/suffix extraction and four additional saved map keys are **not directly observed in the provided native evidence**. They therefore remain inferred, not verified.

## Implemented

The existing production planner and validator now accept an optional explicit catalog parameter while retaining the original `DLC_CATALOG` as the default. This means the same code can statically exercise a six-store set, without turning any unverified keys on in the public patcher. Ordering, isolation, duplicate avoidance, contradiction failure, protected-object hashing, encrypted-save round-trip, and preservation of unknown/edition/Arcade entries are unchanged.

`tests/fixtures/six-store-candidate-catalog.js` contains **test-only proposed** `PackName` values generated by the observed old IAP UniqueNames plus the native-derived StoreFrontGroup name pattern. It is deliberately not imported by the browser application, `js/config.js`, or production `js/auto-patch.js`.

`tests/six-store-static-readiness.test.js` exercises all six groups with the isolated proposed values, including 24 inserted pass entries, four shared IDs, partial ownership, all-owned no-op, extra platform nodes, corruption rejection and the encrypted ZIP/AES round trip. A separate assertion ensures the public default writer still targets only Nintendo and Steam. No six-store synthetic test is represented as a real-store reload check.

## What is required to activate the remaining four groups

1. Confirm whether the v1.25.3 or newer game's ownership map actually uses `Epic`, `Microsoft`, `Sony`, `Apple` as keys, independently of the StoreFrontGroup registry.
2. Confirm the 16 individual DLC `PackName` values, and their saved `PackType`/`Type` fields, through authentic samples or equivalent decisive native value tracing. If a platform has alternate or additional identifiers, update the catalog from the actual evidence instead of forcing the candidate pattern.
3. Verify realistic cross-save map insertion, current profile format and encryption wrapper; test actual old-DLC offline reload on the applicable platform and post-sync behavior separately.
4. Add the now-evidence-backed fields to `DLC_CATALOG.entitlements` and activate only the verified groups in `AUTO_PATCH_PLATFORMS`. The UX remains one-step automatic for all activated groups; never introduce a platform picker or a patch button.
5. Re-run the full Node suite, Chromium E2E and genuine owned/missing/partial/malformed save tests. Inspect PR head and conflict status before proposing a release.

Do not merge this unverified six-store feature just because the isolated implementation and regression tests succeed. Preserve AppleArcade exclusion and edition non-modification. When The Keepsake Sea data arrives, apply the same evidence gate to the new pass rather than deriving its ID from chronological numbering.
